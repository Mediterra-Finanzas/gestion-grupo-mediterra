## 2. Feature flag — corrección importante

El proyecto es **Create React App**, no Vite. Por lo tanto:
- El flag se lee con **`process.env.REACT_APP_AUTH_DUAL`** (string `'true'`), **NO** `import.meta.env` (eso es Vite).
- La URL del endpoint y la config del sandbox también: `process.env.REACT_APP_OSIRIS_AUTH_URL`, `process.env.REACT_APP_SUPABASE_URL_SANDBOX`, `process.env.REACT_APP_SUPABASE_ANON_KEY_SANDBOX`.
- `.env.local` ya tiene `REACT_APP_SUPABASE_URL_SANDBOX` y `REACT_APP_SUPABASE_ANON_KEY_SANDBOX`. Faltaría agregar `REACT_APP_AUTH_DUAL` (default ausente/`false`) y opcionalmente `REACT_APP_OSIRIS_AUTH_URL`.
- **CRA inyecta `REACT_APP_*` en build-time.** Con el flag ausente, `process.env.REACT_APP_AUTH_DUAL === 'true'` es `false` → todo el código nuevo queda inerte (regla #1 y #2 satisfechas).

## 3. Refresh sin PIN (refinamiento de CAMBIO 2)

El PIN solo se necesita para la **sesión inicial** (`ensureSupabaseSession`). El **refresh NO necesita PIN**: usa el `refresh_token` contra `${SANDBOX}/auth/v1/token?grant_type=refresh_token`. Por lo tanto, al **restaurar sesión** (L1678, sin PIN):
- Si hay `access_token` en sessionStorage y no expiró → usarlo.
- Si expiró pero hay `refresh_token` → `refreshOsirisSession()` (sin PIN).
- Si no hay nada o el refresh falla → **degradación graceful**: Osiris relacional sin sesión (0 filas + mensaje), el resto de la app intacto.

Esto evita el problema del PIN ausente en el restore y es más robusto que "no hacer nada".
