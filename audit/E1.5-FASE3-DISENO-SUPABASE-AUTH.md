## 1. Propósito

Cliente del endpoint `osiris-auth` (Fase 2). Obtiene, guarda, refresca y limpia una sesión Supabase Auth del **sandbox** para Osiris relacional. Es un **helper puro**: no toca UI, no lanza excepciones al caller, y degrada con gracia. El gating por feature flag lo hace `App.jsx` (CAMBIO 2); este módulo no depende del flag.

## 2. Configuración (CRA → `process.env.REACT_APP_*`)

| Var | Uso | ¿Existe en `.env.local`? |
|---|---|---|
| `REACT_APP_OSIRIS_AUTH_URL` | URL del endpoint. Si falta, se **deriva**: `${REACT_APP_SUPABASE_URL_SANDBOX}/functions/v1/osiris-auth` | A agregar (opcional) |
| `REACT_APP_SUPABASE_URL_SANDBOX` | URL del sandbox (para refresh) | Sí |
| `REACT_APP_SUPABASE_ANON_KEY_SANDBOX` | `apikey` de los requests (Edge Function + refresh) | Sí |
| `REACT_APP_AUTH_DUAL` | Flag — lo lee `App.jsx`, no este módulo | A agregar (default ausente = off) |

> Como la URL se deriva del sandbox, configurar `REACT_APP_OSIRIS_AUTH_URL` es opcional. Igual conviene fijarla explícita en Vercel para claridad.

## 3. Almacenamiento

`sessionStorage` (regla #5/#6 — nunca localStorage, nunca cookies). Keys:

| Key | Contenido |
|---|---|
| `osiris_access_token` | JWT de sesión (Bearer para Osiris relacional, cuando exista su data layer) |
| `osiris_refresh_token` | token de refresco |
| `osiris_token_exp` | epoch (segundos) de expiración (`expires_at`) |
| `osiris_rol` | `admin` / `editor` / `viewer` |

Acceso vía wrappers `ssGet/ssSet/ssDel` con `try/catch` (el `sessionStorage` puede lanzar en modo privado/embebido). Margen de expiración: **60 s** (un token se considera expirado 60 s antes para no usarlo al límite).

## 4. API pública (5 funciones)

### `ensureSupabaseSession(email, pin) → Promise<{ ok, error?, rol_osiris? }>`
Llama a la Edge Function con `{ email, pin }` (header `apikey` = anon sandbox). Si responde 200 con `access_token`, guarda la sesión y devuelve `{ ok:true, rol_osiris }`. Si responde 4xx/5xx o falla la red, devuelve `{ ok:false, error }` y **no lanza**.
- `error` posibles: `invalid_credentials` (401), `account_inactive` (403), `bad_request` (400), `internal_error` (500), `http_<status>`, `network_error`, `not_configured`.
- **Nunca** loguea el PIN ni el token (solo `status` + `error`).

### `getOsirisAccessToken() → string | null`
Devuelve el `access_token` **vigente** (existe y `exp - 60 > now`). Si no hay o expiró, `null`. **No** refresca por sí solo (eso es responsabilidad explícita del caller vía `refreshOsirisSession`).

### `refreshOsirisSession() → Promise<string | null>`
Usa el `refresh_token` contra `${SANDBOX}/auth/v1/token?grant_type=refresh_token` (sin PIN). Devuelve el nuevo `access_token` o `null`.
- Si el refresh es **rechazado** (400/401 = inválido/expirado) → `clearOsirisSession()` y `null` (evita loops).
- Si es **error de red** (transitorio) → `null` **sin limpiar** (se puede reintentar luego).

### `clearOsirisSession() → void`
Borra las 4 keys de `sessionStorage`. Idempotente.

### `hasOsirisSession() → boolean`
Check rápido: `true` si hay token vigente **o** un `refresh_token` disponible (sesión usable o recuperable). Útil para decidir si mostrar Osiris relacional o el estado degradado.

## 5. Manejo de errores (contrato de robustez)

- Ninguna función `throw`-ea al caller. Todo error se captura → `console.error` con metadata (status/mensaje), nunca con secretos.
- `ensureSupabaseSession` siempre resuelve a `{ ok:false, error }` ante fallo.
- `refreshOsirisSession` distingue **rechazo** (limpia) de **red** (no limpia).
- Falta de config (`endpoint`/`anon`) → `{ ok:false, error:"not_configured" }`, no crash.

## 6. Ejemplos de uso (para CAMBIO 2, referencia)

```js
import {
  ensureSupabaseSession, getOsirisAccessToken,
  refreshOsirisSession, clearOsirisSession, hasOsirisSession,
} from "./data/supabase-auth";

const DUAL = process.env.REACT_APP_AUTH_DUAL === "true";

// (a) En handleLogin (camino normal), fire-and-forget — no bloquea el login:
if (DUAL) {
  ensureSupabaseSession(emailInput, loginPin.trim())
    .then(r => { if (!r.ok) console.warn("[osiris-auth] sin sesión:", r.error); });
}

// (b) En handleCambiarPin (tras entrar desde PIN temporal), con el PIN nuevo:
if (DUAL) ensureSupabaseSession(worker.email, pinNuevo);

// (c) En doLogout:
if (DUAL) clearOsirisSession();

// (d) Al restaurar sesión (sin PIN): usar token vigente o refrescar; sino, degradar.
if (DUAL && !getOsirisAccessToken()) {
  refreshOsirisSession(); // si no hay refresh válido, queda sin sesión (Osiris relacional degradado)
}
```

> Nota: como `ensureSupabaseSession` es fire-and-forget, **no** se usa `await` en el login para no bloquear la UI (regla #4). El `.then` solo loguea.

## 7. Lo que este módulo NO hace (límites de alcance)

- **No** consume el token en queries de Osiris (eso es CAMBIO 3 / Bloque E2 relacional, fuera de E1.5).
- **No** lee el flag (lo hace `App.jsx`).
- **No** persiste nada fuera de `sessionStorage`.
